# Milestone 3 evidence register

This living ledger links the [traceability matrix](traceability-matrix.md) to foundations and later results. A row may describe an **implementation/tooling foundation**, **executed evidence**, or an **exact-source documentation/control assessment** where documentation or implementation evidence is the contractual deliverable; never infer validation from tooling alone. Runtime and benchmark claims still require real executed records and retained reviewer evidence. A documentation/control assessment validates only its stated review scope and cannot substitute for execution where the claim depends on runtime behavior.

## Adding an executed record

Use the next stable evidence ID (for example `EVD-001`) and complete every field; use **Not applicable** rather than leaving ambiguity. Describe the method generically in public, record source and deployed SHAs separately, and put no secret location or raw private content in the ledger. “Private evidence retained” is only **yes**, **no**, or **not applicable**. A sanitized summary should state pass/fail/partial outcome, measured values where relevant, scope, and known limitations.
